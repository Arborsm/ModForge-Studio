# 工作台设计原则

面向小白用户的工作台 UX 设计要求。改任何工作台页面/编辑器前对照此文件；新原则落地后补充进来。

## 1. 布局

- 编辑器走**悬浮面板**覆盖在画布上（参照 `prototype/map-editor-v2.html` 的形态），不要用固定多栏挤压画布。
- 工作台各页面统一**两栏式**惯用法：左栏列表/变更/导航，右栏内容。一处落地的新布局模式要传播到其他页面。
- **极简 chrome**：删掉标题、介绍、没必要的说明文字和层级；行内操作做成 hover 才显示。

## 2. 交互：全面去填表化

- 把 Content Patcher / 配置文件概念包装成点选操作，尽量消灭手填字段。
- 优先使用项目已有控件（CompactSelect、ResourcePicker、下拉、开关），不用原生散装 input。
- 能从画布/上下文捕获的就自动捕获：点格子捕获图层 + 坐标 + 图块、调色板点选图块、拖拽移动标记。
- 选择器显示**本地化名字**而不是原始 token / 内部名（`[LocalizedText ...]` 必须解析）；同名项合并，只有行为不同时才用内部名做副标题区分。
- 操作不抢上下文：点画布不应把右侧 tab 拽走或打断正在填的表单；开始拖拽标记、添加图层这类操作的选中反馈停留在该操作自身的语义上，不额外切换面板或滚动位置。
- 低频配置收**对话框/popover**：传送落点、音乐、环境光这类不常改的配置不铺在面板里，点开对话框完成（目标地图下拉 + 大预览点选落点），顶栏 chip 配 popover。
- **画布 overlay 涂刷模式**：单元格规则（可通行/阻挡/阻挡 NPC/水域/可种植）不开侧栏表单，工具轨开关后在画布上着色显示规则区域，左下规则条选规则直接拖曳涂刷（「可通行」= 擦除）；一次拖拽只压**一条历史**。
- **控件可用性随主开关联动**：总开关（如户外/室内）同时决定从属控件（环境光 chip、光照预览的黄昏档）的可用性，禁用时用 title 说明原因（如「户外地图的光线由游戏昼夜决定」）。
- 一次用户操作只压**一条历史记录**，历史文案必须是人话。
- hover 显示对应预览（图块缩略图、物品效果等）；长列表默认折叠（前 2 条 + 「查看全部 N ›」链接展开）。

## 3. 分层收纳

- 主界面只放高频语义操作（传送入口 / 门 / 光照这类语义卡片）。
- 语义卡片=24px 图标块 + 两行摘要，编辑/删除等操作 **hover 才显示**；添加操作收纳在**段头右侧的 ＋**（操作指引放 title，不占正文）。
- 高级能力一律收进折叠：原始属性编辑器、外部 tsx 引用、对象组管理等，摘要标注「高级：xxx」。

## 4. 视觉

- 配色一律走 `tokens.css` 主题变量，禁止写死颜色字面量；视觉问题优先直接改 token，不打零散 `.dark` 补丁。
- **所有浅色主题保持平面白底**，用边框/阴影分层；dark 模式不动。
- 颜色类配置（如环境光）给正经控件（色板 + 预设档），不是三个数字框。
- **「原版默认 + 自定义」色板**：预设只留游戏原版默认色（走数据/常量），其余交给自定义取色，不堆一堆预设档；写回格式与游戏对齐（如空格分隔十进制 RGB）。

## 5. 文案

- UI 文案全部走 `src/locales` 的 typed locale bundles（zh-CN / en-US 同步），组件里禁止硬编码用户可见字符串。
- 去 CP 黑话：不出现「补丁引用 / 图块表 / 序列化」这类词，换成「使用位置 / 图块素材」这种小白说法。

## 6. 工程约束（设计相关）

- 新功能按真实产品路径做完整：数据加载、加载态、空态、错误态、持久化、校验、国际化都要落地，禁止占位 UI 和 MVP 壳。
- 重组件（编辑器）先预热 + 加载态 + 只挂载一次。
- UI/布局变更必须有截图、Playwright 验证脚本或明确手动路径证明，不靠静态阅读宣布完成。
